# 融合老师搜索

项目根目录运行：

```sh
pnpm mix
```

默认输出 `python/checkpoints/mix-v6/`，每步 5 秒、单 worker，降低多个进程争抢 MPS 对比较的影响。
这是一轮正式搜索，包含数百盘对局，可能持续数小时到数十小时；不是快速检查。
任务按配方/对手交错执行。每盘完成立即写入 `games.jsonl`，中断后原命令续跑。
同一输出目录只运行一个进程；变更参数、源码、manifest 或权重需要使用新的 `--output`。
固定种子固定开局和随机战术选择，但限时搜索受机器负载影响，不保证逐手重现。

## 默认阶段

1. **screen**：纯 A3，以及 A3 policy + H3 value 混合，启发式权重 0.25/0.5/0.75。
   对 v6-full、A2、heuristic-v3，每个对手 3 个开局换先（6 局）。共 72 局。
2. **tune**：screen 前两名分别尝试 c_puct=0.8/1.2/1.8；额外比较最佳 value 搭配 A2 policy。
   加纯 A3 基线，每对手 5 个开局换先。至多 240 局。
3. **confirm**：两个非基线入围者和纯 A3，在新的 20 个开局上对三个对手复核。通常共 360 局。
4. **duel**：两个入围者直接对 A3，在 confirm 的相同开局上换先。通常共 80 局。

前两阶段是低成本淘汰，不能用其少量对局证明强弱。确认阶段后不再调参。
panel 综合得分超过 A3，并且直接交手的开局簇 bootstrap 95% 区间下界超过 50%，才建议替代 A3。
这是探索性的两个入围者比较，区间未作多重检验校正；未达到标准时推荐仍为 A3，而不强行选融合模型。
不要把一次搜索理解成证明了全局最高棋力。

## 开局与计时

- 固定前四个 ply：中心黑子、邻近白子，随后黑白在中心 5×5 范围展开。
- 每个开局双方模型换先。screen/tune/confirm 的前缀在 D4 下互不重复。
- 评测续局不用训练式落子采样；固定前缀不是模型自己选出的最佳走法。
- 当前阶段评估正常开局下的中盘棋力，不筛选角落开局，也不修改人机对战开局规则。
- 开始计分前预热模型；搜索预算包括根节点战术检查和初次网络计算。
- 一次不可中断的局面评估仍可能越过截止时间；报告实际对局耗时和候选的平均访问数。
- 使用现有 play_one/MCTS；评测数据保存在本次目录，不写入训练库或累计 Elo。

## 参数

例如允许更多并发（会增加共享设备竞争）：

```sh
pnpm mix --workers 2 --output python/checkpoints/mix-v5-h3
```

扩大确认局数或修改候选网格：

```sh
pnpm mix --screen-pairs 5 --tune-pairs 10 --confirm-pairs 50 \
  --weights 0.25 0.5 0.75 1.0 --c-puct 0.8 1.2 1.8 \
  --output python/checkpoints/mix-v6-expanded
```

`*-pairs` 是每个对手的换先开局对数，每对等于两局。`--time-ms` 默认 5000，`--seed` 默认 0。
每个开局簇 bootstrap 同时重采样该开局下的所有对手与双方颜色；报告不是独立单局置信区间。

## 输出与接入

- `config.json`：参数、固定开局、源码和权重 SHA256。
- `games.jsonl`：带候选配方、开局、种子的逐局记录及搜索统计，续跑依据。
- `screen.json` / `tune.json` / `confirm.json` / `duel.json`：配方、得分率、区间、分对手 W-D-L、耗时/访问量。
- `result.json`：panel 第一名、推荐模型、是否支持替代 A3。
- `teacher-manifest.json`：可合并进正式 manifest 的 `v6-teacher` 条目，包括 c_puct。

搜索不自动修改正式 manifest。查看报告后再将推荐条目合并，随后开始采集 v6 数据。
融合底层模型单次评估内只计算一次；manifest 支持可选 c_puct，现有模型默认仍是 1.2。
Elo 更新现已使用双方更新前的分数，忽略同模型自对弈；历史 Elo 不在此脚本中重算。
